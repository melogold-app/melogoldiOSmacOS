# Melogold для Apple: задание для Claude

Этот файл — задание для сессии Claude, которая пишет клиент Melogold для iPhone, iPad, Mac, Apple Vision Pro и Apple Watch. Прочитай его целиком и работай по нему. Если часть проекта уже сделана иначе, сверь её с документом и покажи расхождения пользователю, прежде чем переделывать.

## 1. Что такое Melogold

- Клиент YouTube Music и обычного YouTube с общей библиотекой на всех устройствах. Начинался как форк ViTune (Android).
- Главный смысл: треки, которые в России вырезали из Apple Music, есть на YouTube (часто перезаливами). Поэтому обычный YouTube — такой же источник, как каталог YouTube Music: видео ищутся, играют, лежат в плейлистах и очереди наравне с песнями.
- Работает без аккаунта. По желанию пользователь входит на сервер Melogold (логин и пароль), и Избранное, плейлисты, сохранённые альбомы и исполнители, история и свои тексты синхронизируются между устройствами. Сервер хранит только метаданные (`videoId` и т. п.). Звук каждый клиент берёт с YouTube сам.
- Части (все репозитории публичные, организация `melogold-app`; локальные клоны — в `/Users/maxim/Documents/melogold/`):
  - `melogoldAndroid` — Kotlin, Material 3 Expressive, выпущен 0.1.3. Эталон поведения и спецификаций — ветка `main` (с 25.09.2026 она совпадает с `redesign/m3e`). Рабочая папка клона может отставать от `origin/main`: свежие файлы читай через `git show origin/main:<путь>`, саму папку не трогай;
  - `melogoldServer` — TypeScript/Node, контракт API (`docs/API.md`);
  - `melogoldWindows` — C#, WinUI 3, выпущен 0.1.2. Ближайший образец по устройству: поток без yt-dlp, SQLite, синк, тексты;
  - `melogoldiOSmacOS` — этот репозиторий;
  - Linux — позже.
- Рабочий сервер: `https://178-250-187-202.sslip.io`, регистрация открыта. Скоро у него будет нормальный домен, старый адрес продолжит работать. Адрес сервера по умолчанию — константа сборки.
- Иконка: `Melogold.icon` (Icon Composer, Liquid Glass: квадраты для iPhone, iPad и Mac, круг для часов) и `Assets/AppIcon-1024.png`. Для Vision Pro в `.icon` слоёв нет — сделай набор visionOS из того же рисунка. Генератор всех иконок — `melogoldAndroid/branding/icon/build.py`.

## 2. Как работает пользователь

- Пишет по-русски. Интерфейс приложения — русский и английский.
- Работай сам и последовательно, по срезам. Срез: сборка и тесты → запуск на симуляторе (и на устройстве, если оно подключено) → скриншоты → коммит → push → показать результат. Субагенты и параллельные воркфлоу — только по просьбе пользователя, и тогда не больше одного.
- Коммиты — conventional на русском (`feat: …`, `fix: …`, `docs: …`), последняя строка — `Co-Authored-By: Claude <модель> <noreply@anthropic.com>`.
- Держи `main` рабочим и сливай в него часто: пользователь хочет видеть прогресс, а не ветки, которые не вливаются.
- Следуй Apple Human Interface Guidelines строго, для каждой платформы — её раздел. Выбирай простоту и единообразие. Нестандартное и декоративное пользователь воспринимает как мусор.
- Если пользователь отверг элемент интерфейса, убери его отовсюду: со всех экранов, включая вложенные, и со всех платформ.
- Если поведение ещё не решено, спроси, потом делай. Решённое не переспрашивай.
- Не поднимай несрочные юридические вопросы, покупки и админские дела. Продолжай строить.
- Пароли пользователя не спрашивай, не вводи и не храни.
- Секреты (сертификаты, ключи, пароли) — только в GitHub Secrets, в репозиторий они не попадают. Кладёт их пользователь или ты — по его явному разрешению (`gh secret set`). Аккаунты и записи в Apple Developer и App Store Connect не создавай.
- Контракт сервера сам не меняй. Если клиенту что-то нужно от сервера, опиши это и скажи пользователю.

## 3. Стек и устройство (решено)

- **Платформы:**
  - iOS, iPadOS, macOS, visionOS и watchOS — минимум 26. Liquid Glass и нужные API SwiftUI (`Tab(role: .search)`, `tabViewBottomAccessory`, стеклянные стили кнопок) есть с 26; старые системы потребовали бы второго дизайна;
  - на Mac пользователя — Xcode 27, Swift 6.4, симуляторы iOS 27, watchOS 27 и visionOS 27;
  - Swift 6 (языковой режим 6, строгая проверка конкурентности), SwiftUI, Observation (`@Observable`), async/await;
  - Mac — нативный SwiftUI, не Mac Catalyst.
- **Проект:**
  - `project.yml` (XcodeGen) — единственный источник проекта. `Melogold.xcodeproj` генерируется командой `xcodegen generate` и тоже лежит в репозитории, чтобы открываться в Xcode без инструментов. `project.pbxproj` руками не правится; CI проверяет, что проект совпадает с `project.yml`. Если XcodeGen не справится с чем-то из Xcode 27 (иконка `.icon`, часы), выбери самый маленький обход и скажи пользователю;
  - таргет `Melogold` — одно мультиплатформенное приложение: iPhone, iPad, Mac, Apple Vision;
  - таргет `Melogold Watch` — самостоятельное приложение watchOS (§5.6): встроено в приложение iOS и ставится на часы вместе с ним, но работает и без него (`WKRunsIndependentlyOfCompanionApp`);
  - идентификаторы — `app.melogold.Melogold` и `app.melogold.Melogold.watchkitapp`. ID команды — вне репозитория: локальный xcconfig в `.gitignore`, в CI — секрет `APPLE_TEAM_ID`.
- **Пакет `Packages/MelogoldKit`** (Swift Package) — всё, что не интерфейс:
  - `MelogoldCore` — чистые правила, порт `:core:domain` Android и `src/Melogold.Core/Domain` Windows: TitleCleaner, ServerAddressPolicy, YouTubeLinkParser, ссылки `melogold://`, модель текстов с LRC и TTML, LyricsDraft (редактор), PlaylistDiff (якоря и наибольшая возрастающая подпоследовательность), правила очереди, `hwid`, proof-of-work;
  - `MelogoldInnerTube` — клиент YouTube Music и YouTube, порт `providers/innertube` Android и `src/Melogold.InnerTube` Windows;
  - `MelogoldServer` — API сервера, сессия, синк библиотеки, истории и текстов, SSE;
  - `MelogoldData` — база, репозитории, отложенные удаления, индекс кэша и загрузок;
  - `MelogoldPlayback` — поток, кэш, плеер на AVFoundation, системный «Сейчас играет»;
  - все модули собираются и для watchOS. Где API на часах нет (§4 «Часы», грабли §9 п. 20), у модуля своя ветка для watchOS;
  - тесты — Swift Testing. `swift test` в пакете гоняет правила, парсеры и векторы без симулятора.
- **Зависимости** (SwiftPM) — только GRDB.swift (SQLite) и Sparkle 2 (только Mac). Остальное — системные фреймворки. Новую зависимость добавляй, только объяснив пользователю, зачем она.
- **Образцы:**
  - Windows-клиент (`/Users/maxim/Documents/melogold/melogoldWindows`) — ближе всех по устройству: поток без yt-dlp, схема SQLite, синк, тексты. Повторяй поведение, код не переводи строка в строку;
  - Apple-клиент Clementine VPN того же пользователя (`/Users/maxim/Documents/VPN/iOS:macOS Clementine`; бери локально, с GitHub не клонируй): SwiftUI для iPhone, iPad и Mac, Keychain, данные устройства, боковая панель на Mac, `Localizable.xcstrings` и `InfoPlist.xcstrings`, `PrivacyInfo.xcprivacy`, скрипт выпуска Mac с Developer ID и нотаризацией (`scripts/publish-macos-release.sh`). Бери приёмы, VPN-специфику не переноси.
- **Данные:**
  - SQLite через GRDB. Схема и имена — как у Windows (`src/Melogold.Core/Data/LibraryDatabase.cs`): `tracks`, `albums`, `artists`, `playlists`, `playlist_items`, `play_events`, `search_history`, `lyrics`, `content_blocks`, `app_state` и снимки синка `sync_state`, `synced_likes`, `synced_bookmarks`, `synced_playlists`, `synced_lyrics`. Чего у Windows ещё нет (например, загрузки и устройство прослушивания), добавляй по Android REWRITE §4.2 и §4.12a в том же стиле. Копия библиотеки при этом общая для всех клиентов, свой формат: `melogoldAndroid/docs/spec/backup-format.md`, задание 0006;
  - схема идёт от модели сервера: трек по `videoId`, плейлист с `syncId`, позиция трека с `sortKey`, лайки, закладки альбомов и исполнителей. Только локально — очередь, кэш и загрузки;
  - база и логи — в `Application Support/Melogold/`. Кэш музыки и загрузки — тоже там, а не в `Caches`: оттуда система стирает файлы при нехватке места, а пользователь этого не хочет (на Android кэш по той же причине перенесли из системного cache в `Android/data`). Папкам кэша и загрузок — `isExcludedFromBackup`, чтобы гигабайты музыки не уходили в резервную копию iCloud. Обложки — в `Caches`;
  - настройки — `UserDefaults` с ключами реестра Android (REWRITE §4.11.5: `shell.lastTab`, `playback.normalization`, `sort.*` и т. д.).
- **Сеть:** URLSession. У каждого потребителя свой User-Agent, глобального нет:
  - InnerTube WEB и WEB_REMIX — браузерный UA своего клиента (Android `providers/innertube/.../models/Context.kt`, Windows `src/Melogold.InnerTube/InnerTubeClient.cs`);
  - клиенты потока и googlevideo — UA и заголовки из `config/stream-clients.json` (§4);
  - сервер Melogold — `melogold-macos/<semver>` на Mac (API §1.2) и `Accept-Language` по языку интерфейса. Для iPhone, iPad и Vision значения в контракте нет (§11);
  - lrclib и kugou — `Melogold/<версия> (+https://github.com/melogold-app/melogoldiOSmacOS)`;
  - домашний сервер по http (API §7.1): `NSAllowsLocalNetworking` и `NSLocalNetworkUsageDescription`, диапазон `100.64/10` — только по https. API называет это для macOS; на iPhone, iPad, Vision и часах ключи те же.
- **Сессия и устройство:**
  - токены — в Keychain (`kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`), не в `UserDefaults`;
  - `hwid` — по API §1.6, векторы `melogoldServer/spec/hwid.vectors.json`. Mac: `platformId` = `IOPlatformUUID` как есть. iPhone, iPad, Vision и часы: `platformId` — случайный UUID v4 в Keychain с `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly` (API §1.6, сервер 651b1a7 и 90f5149): переживает переустановку и не переезжает на новое устройство;
  - `platform` и User-Agent `melogold-<platform>/<версия>` (API §1.2, §1.6): Mac — `macos`, iPhone — `ios`, iPad — `ipados`, Vision Pro — `visionos`, Apple Watch — `watchos`. Часы входят сами и в аккаунте — отдельное устройство (§5.6);
  - `DeviceInput` (имя, `osVersion`, `model`) — как `Networking/DeviceIdentityService.swift` в Clementine; на часах — `WKInterfaceDevice`. На iPhone без особого права Apple система отдаёт имя «iPhone», а не имя владельца, — так и оставь.
- **Логи:**
  - `Logger` (os.log) и свой файл до 2 МБ; при старте он переименовывается в `previous`;
  - последнее падение — из MetricKit (`MXCrashDiagnostic`, приходит при следующем запуске) в отдельный файл. На watchOS MetricKit нет — там только файл лога;
  - «Диагностика»: версии, «Проверить извлечение» (REWRITE §3.5.10), архив логов через «Поделиться»; на Mac — ещё «Показать в Finder».
- **Ссылки:**
  - `melogold://` — `CFBundleURLSchemes` и `onOpenURL` (API §7.2);
  - ссылки YouTube система приложению не отдаёт: домен не наш. Входы — кнопка «Вставить ссылку» в Поиске, вставка в поле, на Mac и iPad — перетаскивание ссылки в окно.
- **Обновления:**
  - Mac — Sparkle 2: DMG и `appcast.xml` в GitHub Releases, подпись EdDSA, проверка при старте не чаще раза в 6 часов и пунктом «Проверить обновления…» (задание 0004);
  - iPhone, iPad, Vision, часы — App Store, тесты — TestFlight (задание 0005). Своего механизма обновления нет;
  - версия — в одном месте (`Config/Version.xcconfig`, `MARKETING_VERSION`), без суффиксов. Номер сборки считается из неё: major×10000 + minor×100 + patch, как `versionCode` Android.
- **CI:** GitHub Actions на macOS-раннере (`macos-26` или новее), Xcode выбирается явно — той же мажорной версии, что на Mac пользователя. Если на GitHub его ещё нет, возьми ближайший и скажи пользователю. На каждый push: `swift test` пакета и сборка `Melogold` для iOS, macOS и visionOS и `Melogold Watch`.

## 4. Воспроизведение (решено, с учётом граблей Android и Windows)

- **Поток:**
  - всё на Swift, без Python и yt-dlp (решение пользователя; App Store, правило 2.5.2). Тот же путь уже работает у Windows: запрос InnerTube `player` клиентами, которые отдают прямые ссылки без расшифровки подписи;
  - сейчас (сентябрь 2026) это VISIONOS: Windows `config/stream-clients.json`, `ClientProfile.VisionOs` в `src/Melogold.InnerTube/InnerTubeClient.cs`. Ему нужен `visitorData`, иначе ответ «Sign in to confirm you’re not a bot»; `visitorData` приходит с любым запросом WEB_REMIX. IOS без PO-токена с августа 2026 отдаёт только начало файла. ANDROID_VR — запасной, googlevideo он читает с тем же User-Agent;
  - список клиентов (имя, id, версия, хост, UA, поля устройства) — `config/stream-clients.json` в этом репозитории, формат как у Windows (`schema: 1`). Приложение берёт сохранённую копию и в фоне подтягивает свежий файл с `main`: `https://raw.githubusercontent.com/melogold-app/melogoldiOSmacOS/main/config/stream-clients.json`. Встроенный список остаётся запасным, негодный файл не применяется. Так поломку на стороне YouTube можно чинить без релиза и без проверки App Store: это данные, а не код;
  - если YouTube закроет все такие клиенты — вторая линия: WEB-клиент с расшифровкой подписи на JavaScriptCore. В 0.1 не делается.
- **Формат:** только AAC в m4a — itag 140, запасной 139. Opus в WebM (251) AVFoundation не играет.
- **Скорость старта:** медиана от нажатия до звука не больше 3 с на Wi‑Fi, p90 — не больше 6 с, по 10 разным трекам. Для этого:
  - адреса двух следующих треков резолвятся заранее;
  - сторож на извлечение — 20 с, одновременно не больше двух извлечений;
  - метаданные трека уже есть в строке: `player` нужен только ради адреса и `loudnessDb`.
- **Плеер:**
  - `AVQueuePlayer` держит текущий и следующий трек (бесшовный переход). Очередью управляют свои правила (ниже), а не плеер;
  - источник — `AVURLAsset` со своей схемой адреса (например, `melogold-audio://<videoId>`) и `AVAssetResourceLoaderDelegate`. Он отдаёт байты из загрузок, затем из кэша, недостающее читает у googlevideo короткими диапазонами HTTP Range и сразу пишет в кэш — как `ChunkedYouTubeDataSource` Android (`service/PlayerService.kt`) и `src/Melogold.Playback/HttpRangeReader.cs` Windows. Так плеер переживает 403 и истечение адреса;
  - `AVAudioSession`: категория `.playback`, политика `.longFormAudio`, фоновый звук (`UIBackgroundModes: audio`). Звонок, Siri и отключение наушников ставят паузу, как в системных плеерах.
- **Система:**
  - `MPNowPlayingInfoCenter`: название, исполнитель (у видео — канал), альбом, длительность, позиция, скорость, квадратная обложка (REWRITE §4.8.2). Заголовок не меняется во время трека;
  - `MPRemoteCommandCenter`: play/pause, следующий и предыдущий, перемотка, повтор и перемешивание (их зовут CarPlay и Siri), ♡ через `likeCommand`;
  - AirPlay — `AVRoutePickerView` в «Сейчас играет». Звук уходит с устройства, поэтому свой загрузчик AirPlay не мешает. Проверь на приёмнике, если он есть у пользователя;
  - Mac: медиаклавиши и «Сейчас играет» в Пункте управления — через те же классы; меню в Dock: ⏮ ⏯ ⏭;
  - CarPlay — аналог Android Auto (REWRITE §3.14.3): списки «Недавние», «Избранное», «Плейлисты», «Скачанное», «Для вас» и «Сейчас играет» с ♡. Нужно право CarPlay Audio от Apple (его запрашивает пользователь, задание 0005); до него CarPlay проверяется на симуляторе;
  - Siri: «Включи … в Melogold» — `INPlayMediaIntent` в самом приложении. Разбор как у Android `VoiceQueryResolver` (REWRITE §3.14.3): лучшая песня, а если песен нет — первое видео, дальше трек и радио. Пустой запрос продолжает очередь.
- **Ошибки** — по REWRITE §4.10.3 и §3.10.9 Android, с теми же текстами:
  - 403 от googlevideo — не пропуск: сбросить адрес в кэше, получить новый и повторить, до двух раз;
  - кэш адресов: LRU на 64 записи, срок — параметр `expire` минус 5 минут, сброс при смене сети (`NWPathMonitor`);
  - повторы: сеть — 2 (через 1 с и 3 с), таймаут — 1, проверка на бота — 1 с другим клиентом;
  - гео-блок, «видео недоступно» и возрастное ограничение — сразу пропуск с понятной причиной;
  - после трёх пропусков подряд воспроизведение останавливается.
- **Громкость, скорость, столбики:**
  - нормализация по `loudnessDb`. Громкие треки тише — через `AVAudioMix`; тихие громче — через `MTAudioProcessingTap` с ограничителем. Если усиление вверх за день не заводится, оставь только ослабление и скажи пользователю;
  - скорость 0,5–2× — одна глобальная настройка в «Настройки › Воспроизведение», тон не меняется (`audioTimePitchAlgorithm`). В меню плеера её нет; если скорость не 1×, в плеере виден чип «1,25×»;
  - столбики «играет» двигаются под реальный звук (низы, середина, верх), а не по кругу. Звук — из того же `MTAudioProcessingTap`, со сдвигом на задержку вывода (Android `service/AudioLevels.kt` сдвигает на 200 мс). При «Уменьшении движения» они стоят. Скажи пользователю, что получилось.
- **Очередь** — по REWRITE §2.3 и §4.10.4:
  - нажатие по треку в списке играет список, по одиночному треку — трек и радио;
  - «Играть следующим» и «В конец очереди»;
  - при замене очереди — «Очередь заменена · Отменить»;
  - в конце очереди — автовоспроизведение похожих без повторов;
  - перемешивание; повтор: выкл · все · один;
  - после перезапуска очередь и позиция восстанавливаются, без автостарта.
- **Таймер сна:** 15, 30, 45 или 60 минут и «До конца трека».
- **Кэш и загрузки:**
  - кэш — задание 0003: 4 ГБ, вытесняется то, что дольше всех не слушали, метка «в кэше» отдельно от «скачано»;
  - загрузки — по REWRITE §4.7: трек, альбом, плейлист, Избранное; состояния, ошибки, «Скачанное». Загрузка идёт, пока приложение открыто или играет музыка; иначе встаёт в ожидание и продолжается при возврате;
  - «Сохранить файлом» (Android `data/downloads/FileExport.kt`): .m4a без перекодирования, с тегами и обложкой — `AVAssetExportSession` passthrough с метаданными. Mac — в `~/Music/Melogold`, iPhone и iPad — системное окно сохранения в «Файлы».
- **Часы** — те же правила очереди, ошибок и адресов, но своя ветка плеера. В SDK watchOS 27 нет `AVAssetResourceLoader` и `MTAudioProcessingTap` (`API_UNAVAILABLE(watchos)`), поэтому:
  - `AVQueuePlayer` получает прямой адрес googlevideo, User-Agent клиента потока — через `AVURLAssetHTTPUserAgentKey`. Диапазоны запрашивает сам AVFoundation;
  - 403 и истёкший адрес — сбросить адрес, получить новый и заменить элемент с той же позиции, до двух раз;
  - кэша потока на часах нет: без сети играет только скачанное. Загрузки — фоновой сессией URLSession (§5.6);
  - нормализация только ослабляет громкие треки (`AVAudioMix`), столбики в строке стоят;
  - формат — 140. Если в проверке на часах по LTE звук прерывается, поток по сотовой сети переходит на 139 (48 кбит/с): Apple советует начинать поток на часах с 64 кбит/с (WWDC19 «Streaming Audio on watchOS 6»).

## 5. Дизайн

### 5.1 Общее

- Цель — нативное приложение уровня встроенных приложений Apple: Human Interface Guidelines (`developer.apple.com/design/human-interface-guidelines`) для каждой платформы, стандартные компоненты SwiftUI. Перед экраном прочитай страницы HIG о его компонентах: вкладки, боковые панели, поиск, списки, меню, панели инструментов, орнаменты, воспроизведение звука.
- Liquid Glass — там, где его даёт система: панель вкладок, панели инструментов, листы, `tabViewBottomAccessory`, стеклянные стили кнопок. Своё стекло поверх контента не рисуй.
- Шрифт — системный, со шкалой Dynamic Type. Иконки — SF Symbols. Цвета — системные; акцент тоже системный (на Mac — цвет, выбранный пользователем в системе). Тема — «Как в системе · Светлая · Тёмная».
- Разделы везде в одном порядке, на часах тоже: Тренды · Новое · Библиотека · Поиск · Настройки (решение пользователя). Приложение открывается в разделе, где пользователь был при выходе (`shell.lastTab`); при первом запуске — «Тренды».
- От Android берутся разделы, поведение и тексты, но не оформление Material.
- **Граница с Apple Music** (REDESIGN §5.5). Пользователь любит UX Apple Music, но требует уважать интеллектуальную собственность Apple: брать идеи, не копировать 1:1. На платформах Apple системный шрифт, SF Symbols, Liquid Glass и `tabViewBottomAccessory` — это HIG, их используем. Не делаем:
  - размытую или «живую» обложку фоном «Сейчас играет» и движущиеся пятна. Фон — мягкий статичный оттенок цвета обложки (доминирующий цвет через Core Image);
  - размытие и масштаб строк текста;
  - копию экранов Apple Music: их раскладки, розово-красного акцента, всегда тёмного плеера;
  - названия «Медиатека» и «Слушать» для разделов.

### 5.2 iPhone

- `TabView` с пятью разделами. «Поиск» — `Tab(role: .search)`: в iOS 26 система сама выносит его отдельной кнопкой к правому краю. Это системное поведение, его не обходи.
- У каждого раздела свой `NavigationStack`. Детальные экраны (альбом, исполнитель, плейлист, выдача) открываются в стеке текущего раздела. Корни разделов — с большим заголовком, как в системных приложениях; вложенные экраны — с обычным.
- Повторное нажатие на активный раздел: во вложенном экране — к корню, в корне — наверх. Если SwiftUI не делает этого сам, сделай.
- Мини-плеер — `tabViewBottomAccessory`: обложка, название, исполнитель, ⏯ и ⏭. Нажатие открывает «Сейчас играет» (переход `zoom` от мини-плеера, закрытие смахиванием вниз). Смахивание вбок — соседний трек (решение пользователя №8 Android); для VoiceOver — действия «Предыдущий трек» и «Следующий трек».
- Нажатие по треку открывает только мини-плеер, «Сейчас играет» не раскрывается (решение пользователя №6).
- iPhone боком: в «Сейчас играет» обложка слева, управление справа (REWRITE §3.10.11).

### 5.3 iPad

- `NavigationSplitView` (решение пользователя): в боковой панели те же пять разделов, в колонке детали — `NavigationStack` раздела.
- В узком окне (Split View, Slide Over) — как на iPhone.
- Мини-плеер — полоса внизу колонки детали на системном стекле. «Сейчас играет» — во весь экран; в широком окне обложка слева, текст справа.
- Альбом и плейлисты в широком окне — две колонки: шапка слева, список справа (REWRITE §3.12).

### 5.4 Mac

- Одно главное окно. `NavigationSplitView` — как в Clementine (`App/MainTabView.swift`): обычный `List` в боковой панели и одна `NavigationStack` на всю колонку детали. Системные стили `TabView` на Mac не используй: они тянут в панель инструментов лишние кнопки.
- В боковой панели — те же пять разделов, ⌘1…⌘5. ⌘F открывает «Поиск» с курсором в поле. «Настройки…» (⌘,) в меню приложения открывает раздел «Настройки».
- **Панель воспроизведения** — внизу окна во всю ширину, как у Windows:
  - слева обложка, название, исполнитель и ♡. Нажатие по обложке открывает «Сейчас играет», по названию — альбом, по исполнителю — исполнителя;
  - в центре ⇄ ⏮ ⏯ ⏭ ⟲ и ползунок перемотки со временем;
  - справа «Текст», «Очередь», AirPlay, громкость и «…».
- **«Сейчас играет»** — поверх содержимого окна. В широком окне обложка слева, текст справа. Во весь экран — стандартный ⌃⌘F.
- **Очередь** — колонка справа (`inspector`).
- **Мини-плеер** — отдельное маленькое окно поверх остальных: обложка, название, ⏮ ⏯ ⏭. Открывается из меню «Окно».
- **Меню «Управление»:** воспроизведение и пауза (пробел, если фокус не в поле ввода), следующий и предыдущий (⌘→, ⌘←), громче и тише (⌘↑, ⌘↓), перемешивание, повтор, таймер сна.
- **Назад** — Esc и ⌘[: закрыть меню и листы → закрыть «Сейчас играет» → шаг назад в стеке раздела.
- **Строки:** щелчок выделяет, двойной щелчок или Return играет — как в системных приложениях Mac. Правый щелчок — контекстное меню.

### 5.5 Apple Vision Pro

- То же приложение, нативная сборка visionOS, а не режим совместимости с iPad.
- Разделы — `TabView`: на visionOS это вертикальный орнамент у левого края окна.
- Мини-плеер — орнамент внизу окна. «Сейчас играет» с текстом — отдельное окно, его можно поставить рядом.
- Отклик на взгляд и стекло окна — системные. Погружающих пространств нет.

### 5.6 Apple Watch (решение пользователя, 25.09.2026)

Часы — самостоятельное приложение, как Apple Music на часах: свой вход, поиск, поток по Wi‑Fi и LTE, загрузки для офлайна, синк библиотеки, истории и текстов, показ текста. От iPhone ничего не зависит: приложение работает, когда iPhone выключен или Melogold на нём не стоит. Прежнее решение «спутник iPhone без своего входа» отменено.

- **Установка:**
  - приложение часов встроено в приложение iOS и ставится на часы вместе с ним;
  - `WKRunsIndependentlyOfCompanionApp = YES` и `WKCompanionAppBundleIdentifier = app.melogold.Melogold`: его можно поставить и из App Store на часах, без приложения на iPhone;
  - WatchConnectivity для работы не нужен. Независимое приложение по правилам Apple само входит и создаёт аккаунт, само просит разрешения и само качает данные («Creating independent watchOS apps»).
- **Код:** правила, InnerTube, сервер и синк, база и плеер — общие, из `MelogoldKit`. Интерфейс часов — свой, по HIG watchOS.
- **Аккаунт:**
  - вход и регистрация на самих часах. Логин и пароль — системный ввод `TextField` и `SecureField`: клавиатура часов, рукописный ввод, диктовка или клавиатура iPhone (Continuity);
  - после регистрации — код восстановления крупно, моноширинным шрифтом, и флажок «Код сохранён». Буфера обмена на watchOS нет, поэтому вместо «Скопировать» — «Поделиться» (`ShareLink`);
  - `platform` = `watchos`, User-Agent `melogold-watchos/<версия>`, `platformId` — UUID v4 в Keychain с `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly` (API §1.2, §1.6; сервер 90f5149). В списке устройств аккаунта часы — отдельная строка со значком часов;
  - вход по коду (API §4.6, режим `request`): часы показывают `userCode`, а вошедший iPhone, iPad, Mac или Vision вводит его в «Аккаунт › Добавить устройство» и выбирает число, которое видно на часах. Android и Windows одобрять пока не умеют. QR на часах — позже: Core Image на watchOS нет.
- **Экраны** — списки в `NavigationStack` (HIG watchOS):
  - корень — список: «Сейчас играет» (когда есть очередь), затем разделы в общем порядке: Тренды · Новое · Библиотека · Поиск · Настройки. Приложение открывается в корне, а если играет музыка — в «Сейчас играет»;
  - Тренды и Новое — простые списки плейлистов и альбомов, без каруселей;
  - Поиск — поле ввода (системный ввод и диктовка) и недавние запросы; выдача — группы Песни, Видео, Альбомы, Исполнители, Плейлисты;
  - Библиотека — Избранное, Плейлисты, Альбомы, Исполнители и каналы, Скачанное, История (недавние);
  - детальный экран — обложка и название, «Слушать», «Перемешать», «Скачать», список треков;
  - строка трека — обложка, название, исполнитель, метка «скачано». Нажатие играет по правилу очереди (§4) и открывает «Сейчас играет»: мини-плеера на часах нет. Меню — долгое нажатие: ♡, «Играть следующим», «В конец очереди», «Скачать» или «Удалить загрузку»;
  - Настройки — аккаунт и сервер; нормализация; «Не сохранять историю»; «Хранилище»: сколько занимают загрузки, сколько свободно на часах, «Только по Wi‑Fi», «Удалить все загрузки»; «О приложении».
- **«Сейчас играет»** — системный `NowPlayingView` (название, обложка, управление, громкость колесиком Digital Crown, выбор наушников) и нижняя панель: ♡, «Текст», «Очередь». Очередь — список: нажатие переходит к треку, смахивание удаляет; перетаскивания на часах нет.
- **Текст** — показ синхронного и обычного текста по §5.7: текущая строка яркая, нажатие по строке перематывает, прокрутка — колесиком. Цепочка поиска — та же, что на iPhone. Редактора, ручного «Найти текст» и импорта на часах нет.
- **Звук** (документация Apple «Playing background audio»):
  - `AVAudioSession` — `.playback` с политикой `.longFormAudio`, фоновый режим `audio`;
  - длинное аудио watchOS выводит только на Bluetooth — наушники или колонку. `activate()` сам берёт знакомое устройство или показывает системный выбор. Если устройства нет, приходит ошибка: «Подключите наушники или колонку» и «Повторить»;
  - динамик часов стороннему приложению доступен только без `.longFormAudio`, то есть без фона, — для музыки не годится. Apple Music играет в динамик по праву системы;
  - `MPRemoteCommandCenter` и `MPNowPlayingInfoCenter` — как на iPhone. Поток и ошибки — §4 «Часы».
- **Сеть** (TN3135 «Low-level networking on watchOS»):
  - URLSession по HTTP и HTTPS доступен всегда — им идут InnerTube, сервер, SSE и тексты. Низкоуровневая сеть (Network framework, WebSocket, потоки) разрешена только во время воспроизведения; мы её не используем;
  - часы переходят между Wi‑Fi, LTE и сетью через iPhone по Bluetooth, переход длится секунды. Запросы переживают обрыв повтором; доступность сети заранее не проверяется — Apple прямо советует на неё не полагаться.
- **Фон:** пока звук не играет, watchOS быстро усыпляет приложение. SSE и синк идут, пока приложение открыто или играет; при открытии — синк; фоновое обновление (`WKApplicationRefreshBackgroundTask`) — не чаще раза в час, бюджет watchOS мал.
- **Загрузки:**
  - одна фоновая сессия URLSession на приложение. Все куски трека (диапазоны по 1 МБ) ставятся сразу: система докачивает без приложения и будит его, а частые перезапуски загрузок из фона она замедляет;
  - адрес потока живёт около 6 часов. Кусок с истёкшим адресом получает новый адрес при следующем открытии приложения;
  - «Только по Wi‑Fi» — `allowsCellularAccess = false`.
- **Место:** перед загрузкой проверяется свободное место (`volumeAvailableCapacityForImportantUsage`). Если после загрузки останется меньше 1 ГБ, загрузка не начинается: «Мало места на часах».
- **iPhone — только удобства, позже:** передача уже скачанного с iPhone на часы (WatchConnectivity `transferFile`). Часы от неё не зависят.

### 5.7 Плеер

- **Пока нет потока:** на месте ⏯ — `ProgressView`, через 3 с подпись «Получаем поток…», через 15 с — «Долго… · Пропустить». При ошибке — причина словами и «Повторить».
- **«Сейчас играет»** (iPhone, iPad, Mac, Vision):
  - обложка: смахивание вбок — соседний трек, нажатие — текст;
  - название, исполнитель (нажатие — исполнитель или канал), ♡;
  - ползунок перемотки: перетаскивание относительное, позиция применяется при отпускании; слева прошедшее время, справа оставшееся;
  - ⇄ ⏮ ⏯ ⏭ ⟲, «Текст», «Очередь», AirPlay, «…»; чипы таймера сна и скорости, когда они активны;
  - фон — мягкий оттенок цвета обложки (§5.1).
- **Синхронный текст** — по `melogoldAndroid/docs/spec/lyrics.md` (раздел «Отображение») и REWRITE §3.10.3, Android `ui/screens/player/modern/SyncedLyricsView.kt`:
  - текущая строка яркая, прошедшие приглушены сильнее будущих, без размытия и масштаба; пословный текст заливается по словам; подпевка — мельче, под строкой;
  - строки второго исполнителя дуэта — у конечного края, как в `lyrics.md` и на Android (сделано по просьбе пользователя 24.09.2026, позже запрета в REDESIGN §5.5);
  - нажатие по строке перематывает;
  - ручная прокрутка останавливает слежение на 3 с, есть кнопка «К текущей строке»;
  - в паузе без слов точки появляются только на время паузы: выскакивают по одной и лопаются перед следующей строкой. Пользователь просил именно так — игриво, как в Apple Music;
  - если синхронного текста нет, показывается обычный;
  - «Не гасить экран, пока открыт текст» — на iPhone и iPad (`lyrics.keepScreenOn`).
- **Меню текста:**
  - переключатель синхронного и обычного текста подписан по тому, что сейчас на экране, а не по настройке;
  - «Найти текст» — поиск по LrcLib, в нём «Импорт из файла» (`.lrc`, `.ttml`);
  - «Редактировать текст» — редактор по `lyrics.md` (раздел «Редактор»), Android `ui/screens/player/lyricseditor/*`. На iPhone, iPad и Mac;
  - сдвиг текста на ±0,1 и ±0,5 с.
- **Меню «…» плеера** — короткое (REWRITE §3.10.5, абзац «Короче»): трек → текст (пока он показан) → таймер сна → «Не показывать этот трек». Группы разделены линиями, заголовков и вложенного «Ещё» нет. Скорость и «Сведения о потоке» — в Настройках.
- **Очередь** (REWRITE §3.10.4): перетаскивание; удаление смахиванием (на Mac — клавишей Delete); блок «Далее — похожие» с переключателем автовоспроизведения; «Сохранить как плейлист», «Очистить». iPhone — лист, iPad и Mac — колонка справа.

### 5.8 Списки, строки, меню

- **Строка трека:** обложка (у видео квадратная), название, под ним исполнитель и альбом, справа длительность и метки: E, «скачано», «в кэше», «YouTube». У играющего трека вместо обложки — столбики.
- iPhone, iPad, Vision: нажатие играет по правилу очереди, долгое нажатие — контекстное меню, в строке кнопка «…». Mac — §5.4.
- **Меню трека** — пункты и порядок по REWRITE §3.11.3, одинаково на всех клиентах:
  - «В Избранное» или «Убрать из Избранного»;
  - «Играть следующим», «В конец очереди», «Добавить в плейлист…»;
  - «Скачать» (или состояние загрузки), «Другие версии», «Включить радио»;
  - «Открыть альбом», «Открыть исполнителя» или «Открыть канал»;
  - «Поделиться», «Не показывать этот трек»;
  - после разделителя — по месту: «Убрать из плейлиста», «Убрать из истории», «Убрать из очереди», «Не интересно».
- Меню Android пользователь однажды уже назвал громоздким. Лишних пунктов не добавляй.
- Видео и песни — равные источники везде: в поиске, строках, очереди. В очереди, мини-плеере и библиотеке у видео квадратная обложка; превью 16:9 — только в выдаче YouTube, на канале и в карусели клипов.
- Порядок в своём плейлисте меняется перетаскиванием; для VoiceOver — действия «Переместить выше» и «Переместить ниже».
- В длинных списках есть фильтр и сортировка, сортировка запоминается (`sort.*`).
- Мультивыбора в 0.1 нет.

### 5.9 Экраны

Содержимое экранов описано в Android REWRITE §3.1–§3.9, вид — по HIG.

- **Поиск:**
  - до ввода — недавние запросы и «Недавно игравшие»; при вводе — «Открыть ссылку», «В библиотеке» и подсказки;
  - «Вставить ссылку» — системная `PasteButton`: буфер читается только по нажатию и без вопроса «Разрешить вставку»;
  - вставленная ссылка YouTube открывает свою цель (REWRITE §2.3, `youtube-links.vectors.json`);
  - выдача: области поиска (`searchScopes`) «Всё · Музыка · YouTube». Тип внутри области — фильтр: в «Музыке» — Песни, Альбомы, Исполнители, Клипы, Плейлисты; в «YouTube» — Видео, Каналы, Трансляции, Плейлисты.

### 5.10 Состояния, отмена, доступность, тексты

- **Четыре состояния** у каждого экрана:
  - загрузка — `ProgressView` по центру видимой области, появляется через 300 мс; скелетонов нет;
  - контент;
  - пусто — `ContentUnavailableView`: иконка, заголовок, одна строка пояснения и 1–3 кнопки;
  - ошибка — тексты REWRITE §3.0 дословно (Offline, Blocked, Parser, Unknown) и кнопка «Повторить».
- Без сети, но с кэшем — строка над списком «Нет сети — данные от 14:02».
- **Отмена:** разрушающее действие выполняется через 5 секунд (Android `PendingMutations`, REWRITE §3.11.9). Пока идёт отсчёт, над мини-плеером видна плашка «Удалено · Отменить». Плашка одна; новая сразу выполняет предыдущее действие. То же действие отменяется системным «Отменить» (⌘Z, встряхивание) через `UndoManager`. При уходе в фон отложенное выполняется сразу.
- **Анимации** — системные. При «Уменьшении движения» остаются только смены состояний.
- **Доступность:** VoiceOver называет строку и её действия; у каждого жеста есть действие VoiceOver; Dynamic Type — до самых крупных размеров; «Повышенный контраст» и «Понижение прозрачности» системное стекло учитывает само. Зона нажатия — не меньше 44 pt.
- **Тексты** — по Android `docs/GLOSSARY.md` (ru и en). Слова «Медиатека» и «Слушать» в названиях разделов запрещены. Строки — String Catalog (`Localizable.xcstrings`), русский и английский обязательны.

## 9. Грабли, на которые уже наступили

**Android и Windows:**
1. **Адрес потока.** 403 от googlevideo и истёкший адрес лечатся повтором со свежим адресом, а не пропуском трека. Ошибка ввода-вывода не должна становиться фатальной.
2. **Клиенты потока** ломаются: IOS без PO-токена отдаёт только начало файла, VISIONOS без `visitorData` просит подтвердить, что вы не бот. Поэтому список клиентов — в JSON, который обновляется без релиза.
3. **googlevideo** не душит короткие диапазоны. Одним запросом файл шёл на эмуляторе Android около 35 КБ/с, кусками — около 640 КБ/с.
4. **Синхронный текст** находится, только если искать правильно:
   - у песен (у них есть альбом) сначала timed lyrics YouTube Music через browse клиента ANDROID_MUSIC (`timedLyricsModel`), потом LrcLib, потом KuGou;
   - у видео LrcLib идёт первым;
   - в LrcLib — очищенное название (TitleCleaner), без названия альбома, ближайшая длительность в пределах max(3 с, 10 %).
5. **Картинки.** Для превью до 360 px бери `mqdefault`, а не 1280×720. Картинки грузи параллельно.
6. **Синк:**
   - `base` на каждой op;
   - треки плейлиста меняй мелкими ops: `items.add` с якорем, `item.remove`, `item.move` для треков вне наибольшей возрастающей подпоследовательности;
   - `items.replace` для ручных правок не используй: он стирает то, что другое устройство добавило;
   - сервер отвечает текущими строками всех затронутых ключей;
   - на 410 — один раз заново с пустым курсором.
7. **Каталог.** Плейлисты длиннее 100 треков догружаются продолжениями. Язык контента — `hl` по языку системы (`ru`), а не `en`.
8. **Индикатор загрузки** — по центру видимой области, а не всего окна под плеером.
9. **Меню не дёргается** при открытии: всё, что в нём показывается, известно до открытия.

**Swift и контракт:**

10. Длины строк — `utf16.count`; ключи порядка сравниваются по байтам (`Array(a.utf8)`); большие целые — `Int64`; время — ISO с миллисекундами и `Z`. Неизвестные поля и значения перечислений не ломают разбор (API §1.3): перечисления из ответов держи строками.

**Apple:**

11. Папки кэша и загрузок в `Application Support` без `isExcludedFromBackup` раздувают резервную копию iCloud на гигабайты.
12. `AVAssetResourceLoaderDelegate` вызывается только для схемы, которую AVFoundation не умеет сама, — поэтому своя схема адреса. Заполняй `contentInformationRequest` (тип m4a, длина, диапазоны), учитывай `requestsAllDataToEndOfResource`, отменённый запрос прекращай.
13. Без подписи командой macOS может спрашивать доступ к связке ключей после каждой пересборки. Отладочные сборки на Mac подписывай командой разработчика.
14. На Apple Silicon код совсем без подписи не запускается: «без подписи» в CI — это ad-hoc (`codesign --sign -`). Неподписанное приложение из интернета на macOS 15 и новее открывается только через «Системные настройки › Конфиденциальность и безопасность › Всё равно открыть».
15. **Sparkle** (опыт Clementine, `scripts/publish-macos-release.sh`):
    - `CFBundleVersion` приложения обязан совпасть с `sparkle:version` в appcast, иначе обновление молча не придёт никогда;
    - `SUFeedURL` и `SUPublicEDKey` проверяй в собранном приложении до публикации;
    - потеря закрытого ключа Sparkle — установленные Mac больше не обновятся сами. Секрет GitHub назад не прочитать, поэтому резервная копия ключа — у пользователя.
16. DMG подписывается и нотаризуется сам, а не только приложение внутри: Gatekeeper проверяет то, что скачали. Приложению тоже нужен `stapler`, иначе первый запуск без сети упрётся в проверку.
17. `xcodebuild … | xcbeautify || xcodebuild …` под `pipefail` молча пересобирает всё при любой ошибке. Так не пиши.
18. На Mac одна `NavigationStack` на всю колонку детали. Без неё у открытой страницы нет «Назад», а свой стек в каждом разделе рисует второй заголовок (Clementine).
19. App Store: `ITSAppUsesNonExemptEncryption = NO` в `Info.plist` (иначе каждая сборка спрашивает про шифрование) и `PrivacyInfo.xcprivacy` с причинами для `UserDefaults`, времени файлов и свободного места.
20. **watchOS** (заголовки SDK watchOS 27): нет `AVAssetResourceLoader`, `MTAudioProcessingTap`, Core Image, AudioToolbox, JavaScriptCore и MetricKit. Длинное аудио играет только в Bluetooth. BSD-сокеты не работают, низкоуровневая сеть — только во время воспроизведения; на симуляторе она разрешена всегда, поэтому сеть часов проверяется на настоящих часах, с iPhone рядом и без него (TN3135).

2. **Импорт и экспорт** (пользователь, 2026-09-25): как на Android, на всех клиентах, в общем формате копии — задание 0006.
3. **Часы — самостоятельное приложение** (пользователь, 2026-09-25): свой вход, поиск, поток, загрузки, синк и текст, без iPhone (§5.6). Прежнее решение «спутник iPhone без своего входа» отменено.
