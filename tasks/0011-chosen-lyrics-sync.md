# Выбранный текст песни переезжает на другие устройства (и не стирается)

Статус: сделано

**Срочно, раньше остальных открытых заданий.** Windows 0.1.10 отправляет на сервер текст, выбранный в «Найти другой
текст», с его настоящим источником (`lrclib`). Apple принимает такую версию, не считает её своей (`isOwn` — только
`file` и `user`) и при следующей отправке **удаляет её с сервера** (`planSends`: в снимке есть, в своих нет →
`DELETE`). Выбор пользователя пропадает на всех устройствах.

Те же задания: `melogoldWindows` (сделано, Windows 0.1.10, коммиты `262c146`, `845d1de`),
`melogoldAndroid/tasks/0009-chosen-lyrics-sync.md`, `melogoldLinux/tasks/0002-chosen-lyrics-sync.md`.

## 1. Что нужно пользователю

Пользователь добавил трек в Избранное на одном устройстве, нашёл для него правильный текст в «Найти другой текст»
(LrcLib), а на другом пришлось искать тот же текст ещё раз: выбор не переехал. Свои набранные и импортированные тексты
переезжают — не переезжает только выбранный из стороннего источника.

## 2. Решение (одинаково на всех клиентах)

API §4.10 это уже разрешает: свои тексты пользователя — «набранные и синхронизированные в редакторе, импортированные из
файла **или выбранные вместо найденного автоматически**»; источники `user | file | youtube_music | lrclib | kugou`.
Контракт не меняется.

1. **Флаг «выбран»** у локального текста трека (новая колонка, по умолчанию `false`).
2. **Выбран = свой:** текст свой, если одна из сторон из `user`/`file` **или** стоит флаг и текст не пустой. Такой
   уходит на сервер со своим настоящим источником (`lrclib`, `youtube_music`, `kugou`).
3. **Флаг ставится:**
   - пользователь выбрал текст в «Найти другой текст»;
   - пришла своя версия с сервера (синк и ответ `mine` в цепочке поиска) — **с любым источником**;
   - найденный здесь автоматически текст совпал с пришедшей своей версией — он становится выбранным.
4. **Найденный автоматически** (флаг `false`, источник не `user`/`file`) по-прежнему на сервер не уходит.
5. **Правка в редакторе** выбранного текста делает сторону `user`, как и раньше.

## 3. Apple

- `MelogoldData`: миграция GRDB — `ALTER TABLE lyrics ADD COLUMN chosen INTEGER NOT NULL DEFAULT 0`; `StoredLyrics.chosen`
  (`readLyrics`, `saveLyrics`, `lyricsColumns`).
- `MelogoldCore/Lyrics/SyncedLyrics.swift`: `StoredLyrics.isOwn` / `LyricsSyncRules.isOwn` — «или `chosen` и текст не
  пустой».
- `SyncStore.ownLyrics()` (`SyncStore.swift:629`): `WHERE … OR (chosen = 1 AND (COALESCE(synced,'') <> '' OR
  COALESCE(plain,'') <> ''))`.
- `LibrarySync.applyLyrics` (`LibrarySync.swift` ~645): сохранять версию с сервера с `chosen = true`; если локальный
  текст тот же (`sameContent`) и без флага — поставить флаг.
- Выбор в `App/Player/LyricsSearchSheet.swift` (`model.services.lyrics.use(result)`) → `chosen = true`; найденное
  цепочкой поиска сохраняет прежний флаг.

## 4. Проверка

- **Юнит-тесты** (`MelogoldKitTests`): выбранный LrcLib — свой, отправляется с `syncedSource = "lrclib"`; без флага — не
  отправляется; версия с сервера с `lrclib` сохраняется с флагом и не попадает в `DELETE`; миграция сохраняет тексты.
- **Живой сервер** (временный аккаунт, удалить после): Windows выбирает LrcLib-текст → Mac/iPhone получает его, после
  синка версия на сервере жива; и обратно.

## 5. Что сделано (Apple, слайс S1 аудита 30.09.2026)

- Колонка `lyrics.chosen` — миграция `lyrics-chosen-v1` (`SyncMigrations`): тексты остаются, а версии, которые сервер уже
  знает (снимок `synced_lyrics`, `rev ≥ 0`), но которые прежние сборки сохранили как найденные, становятся выбранными —
  иначе следующая отправка удалила бы их с сервера. `StoredLyrics.chosen`, `readLyrics`, `saveLyrics`, `lyricsColumns`.
- `LyricsSyncRules.isOwn` и `SyncStore.ownLyrics()`: «или `chosen` и текст не пустой»; выбранный LrcLib-текст уходит с
  `syncedSource = "lrclib"`, найденный автоматически — нет. `LyricsSyncRules.stored` (версия с сервера) — с флагом.
- `LibrarySync.applyLyrics`: версия с сервера сохраняется выбранной; найденный здесь текст с тем же содержимым получает
  флаг (сдвиг остаётся); плюс проверка `changedHere` как у Android — своё, изменённое здесь после прошлого синка, версия с
  сервера не затирает.
- Выбор в «Найти текст» — `LyricsModel.use` → `LyricsStore.choose`: `chosen = true`, источник `lrclib`, обе стороны;
  набранный или импортированный (`user`, `file`) текст без подтверждения не заменяется (лист спрашивает «Заменить ваш
  текст?»). Цепочка поиска: текст из `mine` сервера — выбранный, общий (`shared`) — `melogold`, своим не становится.
- «Очистить кэш» (`clearFetched`, `fetchedSize`) выбранные тексты не трогает.
- Тесты: `LyricsSyncRulesTests` (выбранный — свой, `lrclib` в PUT, версия с сервера не в DELETE, надгробие),
  `SyncStoreTests`/`LyricsStoreTests`/`LyricsMigrationTests`, `LibrarySyncTests` (PUT выбранного, версия `lrclib` не
  удаляется следующим циклом, флаг у совпавшего найденного, `changedHere`), `LiveSyncTests.chosenLrcLibTextTravelsAndIsNotDeleted`
  на локальном сервере. Windows и Android на живом сервере не проверялись — только два устройства Apple и API.
